Overview

The Hospital API provides secure access to patient medical records for emergency situations. This API allows verified hospitals to retrieve comprehensive patient health data including medical history, current medications, allergies, vital signs, and more.

ℹ️
Important: This API is designed for emergency medical situations only. All access is logged and monitored for compliance and security purposes.

Key Features

  • ✅ Comprehensive patient medical history
  • ✅ Real-time vital signs and lab results
  • ✅ Emergency contact information
  • ✅ Current medications and allergies
  • ✅ Automated symptom extraction from consultations
  • ✅ Secure API key authentication
  • ✅ Rate limiting for fair usage
  • ✅ Complete audit trail

Authentication

All API requests must be authenticated using your hospital's API credentials. You will receive these credentials via email after your hospital is verified by our admin team.

API Credentials

API Key: HK_[32-character-hexadecimal]

Your unique hospital identifier

API Secret: [64-character-hexadecimal]

Your secret key (keep this secure!)

⚠️
Security Warning: Never share your API Secret or commit it to version control. Store it securely using environment variables or a secrets management system.

Authentication Requirements

  • Hospital must be verified by admin
  • Hospital account must be active
  • Both API Key and API Secret must be provided in every request
  • Credentials are validated on each request

Response Fields

Patient Information

  • id - Patient unique identifier
  • name - Patient full name
  • age - Patient age (calculated from DOB)
  • gender - Patient gender
  • bloodGroup - Blood type (critical for emergencies)
  • allergies - List of known allergies

Emergency Contact

  • name - Contact person name
  • relationship - Relationship to patient
  • phone - Contact phone number

Medical History

  • chronicConditions - List of chronic medical conditions
  • currentMedications - Active medications with dosage
  • pastSurgeries - Surgical history
  • extractedSymptoms - Symptoms from recent consultations

Clinical Data

  • vitalSigns - Recent vital signs measurements
  • labResults - Laboratory test results
  • recentCases - Recent medical consultations

Access Information

  • accessedBy.hospital - Your hospital name
  • accessedBy.accessTime - Timestamp of access

Common Error Scenarios

Invalid Credentials

If your API Key or Secret is incorrect, you'll receive a 401 Unauthorized response.

{{ '{' }} "success": false, "message": "Invalid API credentials" {{ '}' }}

Patient Not Found

If the patient email doesn't exist in our system, you'll receive a 404 Not Found response.

{{ '{' }} "success": false, "message": "Patient not found" {{ '}' }}

Rate Limit Exceeded

If you exceed 100 requests per hour, you'll receive a 429 Too Many Requests response.

Rate Limiting

To ensure fair usage and system stability, the API implements rate limiting. Each hospital is limited to a specific number of requests per time window.

Handling Rate Limits

Best Practices

  • Monitor the X-RateLimit-Remaining header in your responses
  • Implement exponential backoff when approaching the limit
  • Cache patient data when appropriate to reduce API calls
  • Use the X-RateLimit-Reset header to know when limits reset
  • Handle 429 responses gracefully in your application

Example: Checking Rate Limit

// JavaScript example
const response = await fetch(apiUrl, options);

// Check rate limit headers
const remaining = response.headers.get('X-RateLimit-Remaining');
const limit = response.headers.get('X-RateLimit-Limit');
const reset = response.headers.get('X-RateLimit-Reset');

console.log(`Requests remaining: ${{ '{' }}remaining{{ '}' }}/${{ '{' }}limit{{ '}' }}`);
console.log(`Limit resets at: ${{ '{' }}new Date(reset * 1000){{ '}' }}`);
⚠️
Important: If you consistently hit rate limits, please contact our support team to discuss increasing your quota based on your hospital's needs.
